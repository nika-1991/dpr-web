# DPR: საიტის ყოველდღიური ანგარიშები

ვებ-აპლიკაცია Excel DPR ფაილის (`INFR-TBH-1068-DPR-…xlsm`) ნაცვლად. მასში შესვლა მომხმარებლის სახელითა და პაროლით ხდება.

- **ადმინისტრატორი:**
  - ქმნის მომხმარებლებს და პროექტებს;
  - ტვირთავს ხარჯთაღრიცხვას (BoQ) Excel-იდან;
  - ამატებს თანამშრომლებს პროექტის გუნდში;
  - ადასტურებს ანგარიშებს.
- **თანამშრომელი:** ხედავს მხოლოდ იმ პროექტებს, რომლის გუნდშიც დაამატეს. ავსებს ყოველდღიურ ანგარიშს და აგზავნის დასადასტურებლად.
- **ანგარიშის სექციები:** სამუშაო პირობები, კრიტიკული საკითხები, HSE, შესრულებული სამუშაოები, ხარჯები, პერსონალი, მიღებული მასალა და საწვავი, ვიზიტორები, ფოტოები.
- **სტატუსები:** დრაფტი → გაგზავნილი → დადასტურებული. ხელახლა გახსნისას რევიზია იზრდება (REV+1).
- **პროგრესი:** BoQ-ის ყოველ პოზიციაზე ჯამდება შესრულებული მოცულობა, ჩანს პროცენტი და ვადაგადაცილება.
- **Excel ექსპორტი:**
  - ცალკე ანგარიში ინახება ძველი ფაილის ფორმატით, მაგ. `INFR-TBH-1068-DPR-002-REV01-24.09.26.xlsx`;
  - პროექტის რეესტრი ერთ ფაილში აერთიანებს ყველა დღის სამუშაოს, ხარჯს, პერსონალს და პროგრესს.

## გაშვება Docker-ით (რეკომენდებული)

საჭიროა სერვერი (Linux, Windows ან macOS), რომელზეც დაყენებულია Docker.

1. ფაილში `docker-compose.yml` შეცვალეთ `ADMIN_PASSWORD`.
2. გაუშვით პროექტის საქაღალდიდან:
   ```
   docker compose up -d --build
   ```
3. გახსენით `http://სერვერის-მისამართი:3000` და შედით როგორც `admin`. სისტემა პირველივე შესვლისას მოგთხოვთ საკუთარი პაროლის დაყენებას.
4. „მომხმარებლები“ გვერდზე შექმენით თანამშრომლების ანგარიშები. თითოეულს გადაეცით მომხმარებლის სახელი და დროებითი პაროლი.
5. შექმენით პროექტი და დაამატეთ გუნდი („გუნდი“ ჩანართი). ატვირთეთ ხარჯთაღრიცხვა („ხარჯთაღრიცხვა (BoQ)“ ჩანართი → „ფაილის არჩევა“).

ნიმუშის ჩატვირთვა (პროექტი „თბილისი ჰილსი“ და ანგარიში DPR-002 თქვენი Excel ფაილიდან):
```
docker compose exec dpr npm run seed-sample
```

## გაშვება Docker-ის გარეშე

საჭიროა Node.js 20 ან უფრო ახალი.
```
npm install
ADMIN_PASSWORD="თქვენი-პაროლი" npm start
```
Windows PowerShell-ში: `$env:ADMIN_PASSWORD="თქვენი-პაროლი"; npm start`

თუ `ADMIN_PASSWORD` არ მიუთითეთ, პირველი გაშვებისას სისტემა შემთხვევით პაროლს შექმნის და კონსოლში დაბეჭდავს. მონაცემები ინახება საქაღალდეში `data/`. ნიმუშის ჩასატვირთად სერვერი ჯერ ერთხელ უნდა გაეშვას, მერე: `npm run seed-sample`.

## ინტერნეტში გამოქვეყნება (HTTPS)

ობიექტიდან ტელეფონით შესასვლელად საიტს სჭირდება დომენი და HTTPS. ყველაზე მარტივი გზაა Caddy, რომელიც სერთიფიკატს ავტომატურად იღებს. ფაილი `Caddyfile`:
```
dpr.tesengroup.ge {
    reverse_proxy localhost:3000
}
```
HTTPS-ის ჩართვის შემდეგ `docker-compose.yml`-ში ჩართეთ `COOKIE_SECURE: "true"` და `TRUST_PROXY: "1"`.

## სარეზერვო ასლი

ყველაფერი (ბაზა `dpr.sqlite` და ფოტოები `uploads/`) ინახება ერთ ადგილას: Docker-ის volume-ში `dpr-data` ან საქაღალდეში `data/`. ასლის აღება Docker-ით:
```
docker run --rm -v dpr-web_dpr-data:/data -v "$PWD":/backup alpine tar czf /backup/dpr-backup-$(date +%F).tar.gz -C /data .
```
გირჩევთ, ეს ბრძანება ყოველდღე გაეშვას (cron ან Windows Task Scheduler) და ასლი სხვა დისკზე ინახებოდეს.

## უსაფრთხოება

- **პაროლები:** ინახება bcrypt ჰეშით. მინიმალური სიგრძე 8 სიმბოლოა. დროებითი პაროლი პირველი შესვლისას აუცილებლად იცვლება.
- **შესვლის ცდები:** 5 წარუმატებელი ცდის შემდეგ შესვლა 15 წუთით იბლოკება.
- **სესია:** ინახება HttpOnly ქუქიში 14 დღით (`SESSION_DAYS`). პაროლის შეცვლა ან მომხმარებლის გათიშვა სხვა სესიებს ხურავს.
- **წვდომის კონტროლი სერვერზე:** თანამშრომელი ვერ ხედავს სხვა პროექტს. გაგზავნილ ან დადასტურებულ ანგარიშს ვერ ცვლის. პროექტს და ხარჯთაღრიცხვას მხოლოდ ადმინი ცვლის.
- **დაუცველი ქსელი:** HTTPS-ის გარეშე პაროლი ქსელში დაშიფვრის გარეშე გადაიცემა. ინტერნეტში გასვლამდე აუცილებლად ჩართეთ HTTPS.
